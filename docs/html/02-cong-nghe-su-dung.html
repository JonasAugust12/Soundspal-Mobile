2. Nền tảng: Expo + React Native

Expo SDK 54 & New Architecture

app.json bật "newArchEnabled": true — app chạy trên Fabric renderer và TurboModules thay vì cầu nối (bridge) cũ. Đây là lý do dự án dùng được react-native-nitro-modules (yêu cầu của MMKV 4).

Dự án này KHÔNG chạy được trên Expo Go Có 3 native module không có sẵn trong Expo Go: @react-native-firebase/*, react-native-mmkv, @react-native-google-signin/google-signin. Bắt buộc phải tạo development build: npm run build:android:dev hoặc npx expo run:android.

Cấu hình native được khai báo ở đâu?

Dự án dùng mô hình prebuild: không commit thư mục android/ và ios/ (chúng nằm trong .gitignore). Mọi cấu hình native khai báo trong app.json, và npx expo prebuild sinh ra project native từ đó.

MMKV 4 — lưu trữ

Là gì: key-value store viết bằng C++, nhanh hơn AsyncStorage khoảng 10–30 lần và đồng bộ (không cần await). Có mã hoá sẵn. 

// shared/infrastructure/storage/storage.ts
export const storage = createMMKV({
    id: `${process.env.EXPO_PUBLIC_STORAGE_ID}`,
    encryptionKey: `${process.env.EXPO_PUBLIC_STORAGE_ENCRYPTION_KEY}`,
});
Không bao giờ đổi 2 biến env này trên bản đã phát hành Đổi EXPO_PUBLIC_STORAGE_ID hoặc EXPO_PUBLIC_STORAGE_ENCRYPTION_KEY khiến dữ liệu MMKV cũ không giải mã được → toàn bộ user bị đăng xuất và mất bookmark.

Ai dùng MMKV:

  • mmkvStorage.ts — adapter cho persist của Zustand (3 store)
  • features/notifications/data/deviceInfo.ts — lưu device_id (UUID tự sinh) để backend nhận diện thiết bị ổn định qua các lần mở app

6. Mạng: Axios + Socket.IO

Axios 1.13

Ba thứ đáng nhớ trong apiClient.ts:

  1. Request interceptor gắn token tự động Đọc accessToken từ useAuthStore.getState() — dùng getState() chứ không phải hook, vì đây không phải component React.
  2. Response interceptor + hàng đợi refresh Bắt 401 → refresh token một lần duy nhất → các request khác xếp hàng trong failedQueue chờ token mới. Chi tiết ở tài liệu kiến trúc.
  3. createApiCall() — factory sinh hàm gọi API Mọi datasource đều dùng nó. Tự tách params (GET) và data (khác), tự đặt Content-Type — trừ FormData, vì axios phải tự sinh boundary.
Giới hạn đã biết của Axios trên React Native Axios 1.x không gửi được FormData trên RN — body tới server rỗng và báo ERR_NETWORK (không có status, không có data). Đó là lý do dự án có postMultipartWithFetch() dùng fetch thay thế. Xem bảng "hai con đường upload" bên dưới.

Socket.IO client 4.8

socketService.ts là singleton (class có một instance export sẵn). Điểm đáng chú ý: token được gửi ở ba chỗ cùng lúc để tương thích với mọi cách backend đọc: 

io(process.env.EXPO_PUBLIC_SOCKET_URL, {
    path: process.env.EXPO_PUBLIC_SOCKET_PATH,   // mặc định /socket.io
    auth:  { token: accessToken },               // 1. handshake auth
    query: { token: accessToken },               // 2. query string
    extraHeaders: {                              // 3. HTTP header (chỉ có tác dụng ở polling)
        Authorization: `Bearer ${accessToken}`,
        'x-user-id': user.id,
    },
    transports: ['websocket', 'polling'],
    reconnection: true,
    reconnectionAttempts: 5,
    reconnectionDelay: 1000,
    reconnectionDelayMax: 10000,
})

Ngoài cơ chế reconnect sẵn có của Socket.IO, service còn tự quản lý backoff mũ 2 (1s → 2s → 4s → 8s → 10s) và sau 5 lần thất bại thì đặt cờ hasReachedMaxAttempts để ngừng hẳn, tránh vòng lặp gọi mạng vô tận làm tốn pin.

7. Form: React Hook Form + Zod

Là gì: React Hook Form quản lý state form theo cơ chế uncontrolled (ít re-render). Zod định nghĩa schema và tự suy ra kiểu TypeScript. @hookform/resolvers nối hai thứ lại.

Chỉ áp dụng nhất quán ở một phần dự án RHF + Zod được dùng trong feature auth và 3 form hồ sơ nghệ sĩ (BasicInfoForm, ContactInfoForm, SocialLinksForm). Còn lại — form tuyển dụng, form hồ sơ venue, các modal — dùng useState thuần và validate thủ công. Đây là nợ kỹ thuật, không phải thiết kế có chủ đích.
